# Harness phase 3, M5: replay old reviews

## Purpose

This is the milestone plan for M5 of `plans/active/harness-phase-3.md`.  It gives more detail than the parent plan's M5 section, which stays the criteria.  After M5:

* Six old review rounds of this repo have run again in the test harness, with the agents and the skill of this branch.  Each ran once, with no tuning (D5).
* `docs/reviews/replay.md` holds the ground truth of each case, written and committed before any run.  It also holds the result (x of n found, for each case and in total, with a 95% interval), the cost, each reviewer's verdict counts, the found findings outside the ground truth, and the threats.
* A found finding outside the ground truth that is still on `main` has a `docs/tech-debt.md` entry, or is listed for its own PR.

M5 changes no code that ships, and no agent, skill or guard text.  A miss is recorded, and M6 goes on (D5).

### Step 5: the six cases

The team leader runs the cases one at a time, in the table's order: `pr9`, `m9`, `m11`, `m2`, `m10`, `m18a`.  Each case gets a new clone `replay-<case>-1`, the case command in the background, and `replay-check.sh replay-<case>-<n>` after.

* A case counts only if the Result, Load and Route checks pass.  Otherwise (an error result, a usage limit, the skill not loading, a routed reviewer with no output) it runs again in a new clone `replay-<case>-<n+1>`, with no change, and Progress records why. ### Step 6: compare, flag, and record

1. The team leader extracts, for each counted case, the found findings and the unvalidated nits from `<run>/1/findings.md` (each `### <ID>` block whose verdict is `confirmed`, `pre-existing`, or `unvalidated` with severity `nit`), with `awk` or `sed`, into the scratchpad, in two lists.
2. A new comparer subagent for each case (in one message; six at most) gets the two lists only: the case's ground-truth table, and its found findings with its unvalidated nits, marked as such.  It reads no file.  Its prompt: mark each ground-truth item `found` (by a reviewer, by `cargo-mutants`, or both, from the finding's sources) or `missed`.  An item is found when a found finding states the same defect at the same place (the same file, and the same function or test; for a weak-test item, either of its two places; the item's line ranges tell whether a finding's line is in one), in any words.  A ground-truth item of severity `nit` may also be found by an unvalidated nit; the result marks it `found (unvalidated)`.  A finding that names only the area, not the defect, does not match.  A missed mutant matches an item that is a weak test of the same function.  Give the matching finding's ID and a quote of at most 30 words.  Then list each found finding that matches no item (the outside findings), with its ID and severity.
3. At the same time, a new flag subagent reads `.claude/agents/*.md`, `.claude/skills/review-rounds/SKILL.md` and the ground-truth section of `docs/reviews/replay.md`.  It flags any text in the agent files or the skill that names a ground-truth item: its defect, or its place together with its kind of defect.  It quotes each flag, with the file and line.  A general method, such as "check that each test fails on wrong code", is not a flag.
4. The old round's reviewer tokens come from phase 2's Progress or commit messages where they are recorded, read by the team leader with `git show` and `grep`; else "not recorded".  No agent of M5 reads the old session transcripts under `~/.claude/projects/`: auto mode refused that read in plan review round 3 (classifier reason "PII Data Handling"), and the parent plan does not let an agent try a refused action another way.  The report to the orchestrator names the refusal, and `replay.md` records the gap as a threat.
5. A new checker subagent gets the outside findings of all cases, with their blocks, and checks each against `main` (`git show main:<file>`): `still on main`, `fixed on main` (with the commit, if found), or `gone` (the code no longer exists).  It reports each in one line.
6. The implementer writes the rest of `docs/reviews/replay.md`, in one commit with the Progress line:
   * `## Harness`: the commands (the text of `replay-clone.sh` and `replay-check.sh`, and the case command), the allow list, the model and effort, and the commit whose agents and skill ran.
   * `## Result`: for each case, x/n, and the table of its items with `found` or `missed`, by whom, the matching finding's ID and the quote; the total x/n and its 95% Wilson score interval ([Wilson, 1927](https://doi.org/10.1080/01621459.1927.10502953)), to two decimals; the total again without the `found (unvalidated)` items; the bar (0.8 or more, and each `should-fix` or worse found, where only a severity as recorded counts, not an inferred one) and whether it is met.  The bar uses the parent plan's count, without the `found (unvalidated)` items; the total with them is extra information.
   * `## Cost`: for each case: agents by type, the session's tokens (from `modelUsage`), each agent's final context, `total_cost_usd`, wall time, the `dontAsk` denials and, apart, the guard refusals, the mutants line; and the old round's reviewer tokens.
   * `## Reviewers`: for each reviewer, the counts of `confirmed`, `pre-existing` and `refuted`, summed over the cases.
   * `## Outside findings`: each one, with its case, ID, severity, source, one-line claim and the checker's state.  The maintainer classes a sample of them as real or false after the PR is ready.
   * `## Flags`: the flag subagent's result.
   * `## Threats`: the parent plan's five, and each one that M5 found (a failed Mutants check, a re-run, a denial).
   * An ID in a quoted claim must be defined in `docs/tech-debt.md` or `docs/invariants.md`, since `docs-check` fails an undefined one (M4, Surprises); the implementer rewords a claim that names one.
7. Each outside finding that is still on `main` gets a `docs/tech-debt.md` entry in the same commit, unless the team leader lists it for its own PR.  Findings of one gap share one entry.  (An outside finding is never a nit, since the skill validates no nit.)
